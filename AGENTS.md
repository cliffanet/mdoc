# Правила и ограничения при работе с проектом mdoc

## Общее описание

mdoc - это текстовый конвертер MarkDown формата. Предназначен для упрощённого конвертирования
без применения сложных проектов вроде pandoc.

## Структура директорий

- в корне только:
    - md - исполняемый файл
    - lib - директория со всеми используемыми модулями
- lib/txt.pm - отвечает за текст и координаты в исходнике.
- lib/prs.pm - собственный Markdown/YAML-парсер.
- lib/out - директория с модулями рендеринга в нужные текстовые форматы (html/pdf)
- doc - директория с документацией
- test - директория с тестовыми исходными документами

Взаимодействовать с файлами и папками вне основной директории проекта (mdoc) нельзя. Вся работа только внутри.

## Запуск и проверка работы

Для выполнения конвертирования необходимо выполнить:

```bash
./md [options] source destination
```

- source - исходный md-файл
- destination - файл, в который нужно выполнить конвертирование

Формат файла destination определяется по расширению или через параметр: -t, --type

## Тестовые документы

- тестовые Markdown-документы размещаются в директории `test`
- имя файла должно отражать проверяемый синтаксис или сценарий
- `test/md-syntax.md` содержит примеры всех поддерживаемых конструкций Markdown и должен обновляться при изменении синтаксиса парсера
- тестовый документ должен быть самостоятельным и пригодным для запуска через `./md`
- результаты конвертирования не являются тестовыми исходниками и не должны сохраняться в репозитории
- в файле md-syntax.md содержатся поддерживаемые конструкции и модификаторы
- в папке unsupported/ находятся md-файлы с неподдерживаемыми конструкциями
- по мере доработки конвертера неподдерживаемые ранее конструкции следует переносить из unsupported/ в md-syntax.md

## Требования к изменениям файлов

- не менять содержимое файла, если этого не требует поставленная в чате задача
- там, где правки определены поставленной задачей, менять файлы только в тех местах, где требует задача, остальное содержимое не менять, даже если оно не соответствует перечисленным правилам
- для css, js, html и perl файлов tab-отступы: 4 пробела
- не делать рефакторинг существующих файлов, только делать необходимые правки, исходя из поставленной задачи
- при выполнении правок, сохранять стилистику и форматирование написания файлов
- структура файлов и имена файлов не должны меняться без необходимости
- по завершению выполнения задачи необходимо перечислить все изменённые файлы и описать изменения, сделанные в этих файлах

### Требования к perl-коду

- по возможности используем существующие функции, методы и модули
- при модификации функции метода необходимо скорректировать её описание

### Правила генереции MarkDown

- у таблиц должны быть выровнены вертикальные линии
- содержимое ячеек таблиц должно быть выровнено согласно выравниванию в колонке
