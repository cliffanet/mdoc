# Формат данных для выходного модуля

## Массив текстовых элементов

В блоках содержимого часто встречается термин "массив текстовых элементов".

Это абзац из различных текстовых составляющих, являющиеся частью этого абзаца:

- Объект Str - стандартный текст,
- хеш, где поле 'type' указывает тип элемента:
    - bold (text - массив подэлементов),
    - italic (text - массив подэлементов),
    - strike (text - массив подэлементов),
    - sup (text - массив подэлементов верхнего индекса),
    - sub (text - массив подэлементов нижнего индекса),
    - underline (text - массив подэлементов),
    - mark (text - массив подэлементов),
    - escape (text - экранированный ASCII-знак пунктуации),
    - inlinecode - цитата в виде элемента внутри абзаца (str - содержимое),
    - image - изображение (url, text [необязательное], alt [необязательное], title [необязательное]);
        разрешённое ссылочное изображение содержит исходный text и простой видимый alt.
        В PDF изображение пропорционально уменьшается до доступной ширины текущего
        текстового блока, если его исходная ширина больше; небольшие изображения
        не увеличиваются. Ограничение по высоте страницы не применяется
    - href - ссылка (text - массив подэлементов, url, title [необязательное])
    - fnref - ссылка на сноску (code - исходная метка, num - видимый номер,
        id - якорь места упоминания, target - якорь текста сноски)

Временные inline-элементы badge заменяются парсером на разрешённые image или
буквальный текст неизвестной метки. Блочные badgedef сохраняются в дереве и по умолчанию
игнорируются базовым выходным модулем.
Неизвестные fnref заменяются исходным буквальным текстом до вызова выходного
модуля.

В PDF обычные пробельные границы переноса имеют приоритет. Если неделимый
inline-текст всё равно превышает ширину блока, он аварийно переносится между
графемами без добавления дефиса. Это относится также к ссылкам и строчному
коду; единственная графема, которая шире блока, остаётся целой.


## Блоки

Вызываются одноимёнными методами, в которые передаются аргументы.

### modifier

Модификаторы разметки страницы.

* name - имя модификатора:
    * pagebreak - разрыв страницы
    * toc - оглавление; поле content содержит список элементов с deep, id и title
    * left - последующее горизонтальное выравнивание влево
    * right - последующее горизонтальное выравнивание вправо
    * center - последующее горизонтальное выравнивание по центру
    * justify - последующее горизонтальное выравнивание по ширине
    * vcenter - вертикальное выравнивание следующего верхнеуровневого абзаца

Все модификаторы сохраняются в дереве на исходных позициях. Парсер заранее
назначает горизонтальные значения затронутым абзацам и таблицам, поэтому выходной
модуль игнорирует left, right, center и justify. Модификатор vcenter аналогично
задаёт полю valign следующего верхнеуровневого text значение c и сам игнорируется.
Между vcenter и абзацем могут находиться любые другие модификаторы: они не
завершают ожидание и обрабатываются независимо.

### header

Заголовок.

* deep - глубина вложенности: 1 - самый верхний уровень,
* id - уникальный идентификатор заголовка для ссылок,
* content - массив текстовых элементов.

### listitem

Элемент списка.

* mode - тип списка:
    * ord - нумерованный
    * символ "*", "-" или "+" - с указанным символом перед списком
* num - номер элемента для нумерованного списка,
* mark - разделитель номера "." или ")" для нумерованного списка,
* task [необязательное] - состояние task-пункта: off, on или mid,
* title - заглавное содержимое элемента списка (массив текстовых элементов), первый абзац,
* content - вложенное содержимое (массив текстовых элементов).

### badgedef

Определение ссылочного изображения.

* code - исходная метка,
* url - адрес изображения,
* title [необязательное] - подсказка.

### fndef

Глобальное определение сноски. Сохраняется в исходном месте дерева и по умолчанию
игнорируется.

* code - точная исходная метка,
* content - массив блочных элементов текста сноски.

### fnlist

Итоговый блок использованных сносок, добавляемый в конец документа.

* content - список элементов с полями:
    * num - видимый номер,
    * id - якорь сноски,
    * refs - список якорей всех мест упоминания,
    * content - блочное содержимое определения.


### hline

Горизонтальная линия.

* title [необязательное] - текст заголовка (массив текстовых элементов).

### table

Таблица.

* mode - тип таблицы
    * 1 - стандартная с вертикальными разделителями колонок
    * 2 - облегчённая, только горизонтальные разделители рядов
* width - массив ширины колонок,
* align - массив эффективных выравниваний в колонках:
    * l - left,
    * c - center,
    * r - right,
    * j - justify

Для mode 1 явные маркеры колонок имеют приоритет, а колонки без маркера получают
текущее состояние документа. Для mode 2 оно назначается всем колонкам.
* hdr (только для типа "1") - массив с текстом в заголовках, каждый заголовок - массив текстовых элементов
* row - массив строк, в каждой строке массив ячеек, каждая ячейка - массив текстовых элементов

### code

Блок кода.

* lang (усли указан) - язык, которым должен подсвечен синтаксис
* text - массив строк (хеши: row, col, str).

### quote

Цитируемый блок.

* content - вложенное содержимое (массив текстовых элементов).

### textblock

Вложенный текстовый блок.

* text - массив строк (хеши: row, col, str).

### text

Абзац.

* text - массив текстовых элементов,
* align [необязательное] - горизонтальное выравнивание: l - влево, r - вправо,
    c - по центру, j - по ширине. Обычные абзацы получают значение всегда;
    абзацы сносок его не наследуют,
* valign [необязательное] - вертикальное выравнивание; c - последняя постраничная
    часть абзаца по центру оставшейся области PDF-страницы.

В PDF отсутствие align и значение l означают левое выравнивание. Значения r и c
смещают каждую строку. В режиме j растягиваются только строки, после которых был
перенос; последняя строка абзаца остаётся выровненной влево.
